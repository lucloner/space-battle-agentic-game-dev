Space Blaster — Agentic Game Development Workshop

Watch specialized AI agents build a space-shooter from scratch — live, on your local GPU. No cloud. No API keys.

Authors: Krishna Sivakumar and Xun Wang

Source

What You'll Learn Today

By the end of this workshop you will have:

  • Agentic AI workflows — how to break a complex task into specialized sub-agents that each own a layer of the codebase
  • Game architecture — how a canvas renderer, physics engine, and gameplay state machine fit together in a single HTML file
  • On-device inference — running a 35B-parameter model locally on AMD Ryzen AI hardware with Lemonade Server + ROCm
  • OpenCode TUI — navigating Build Mode, switching agents, and iterating on code through natural-language prompts
  • Prompt engineering for code agents — giving short, effective instructions that produce working features in one shot

And you'll walk away with a fully playable space shooter you built (mostly) by typing English.

How this workshop works

You start with a single nearly-empty game.html. Three pre-written AI sub-agents build it step by step using OpenCode connected to Lemonade Server running locally on AMD Ryzen AI Max 395 (Strix Halo).

Once the base game is running, you take over and push the agents further with new feature challenges.

Workshop flow

Navigate to the project folder:

cd space-blaster-workshop

Step 1 — Launch OpenCode with Lemonade

From inside the project folder:

lemonade launch opencode

Lemonade starts the inference server and launches OpenCode in one command. You will be prompted to select a model recipe:

Select a recipe to import and use with Opencode:
  0) Browse downloaded models
  1) GLM-4.7-Flash-GGUF-NoThinking.json
  2) GLM-4.7-Flash-GGUF-ThinkingCoder.json
  3) Gemma-4-26B-A4B-NoThinking.json
  4) Gemma-4-26B-A4B-ThinkingCoder.json
  5) Qwen3.5-35B-A3B-NoThinking.json
  6) Qwen3.5-35B-A3B-ThinkingCoder.json
  7) Qwen3.6-35B-A3B-NoThinking.json
  8) Qwen3.6-35B-A3B-ThinkingCoder.json

Select option 8 — Qwen3.6-35B-A3B-ThinkingCoder

Option 7 (NoThinking) is faster. Option 8 reasons through the code more carefully — recommended for the best results during the workshop.

Step 2 — Confirm agents are loaded

Inside OpenCode, type:

/agents

You should see:

ui-renderer
physics-movement
gameplay-rules
vfx-polish      (optional)
boss-ai         (optional)

You are all set. Press Esc to start building the game.

Build the game — invoke agents in order

Important: You must be in Build Mode to invoke agents. When OpenCode launches you'll be in Chat Mode by default. Press Tab to cycle through modes until you see Build in the bottom status bar. Build Mode allows agents to write and edit files — Chat Mode will only talk about code without changing anything.

Step 3 — Visual layer

While in Build Mode, select the ui-renderer agent by typing @ui-renderer and giving it the prompt:

@ui-renderer build the visual foundation of the game

This may take 2-3 minutes while the model generates code. Sit back and watch the agent work!

→ Canvas, star-field, ship art, enemy shapes, HUD, and draw loop written into game.html

Check your progress (optional): In a new terminal, open game.html in a browser to see the visual foundation the agent just built. You should see a canvas with a star-field and ship art — no gameplay yet.

Note: When the browser opens you may see a system dialog that says "Choose password for new keyring". This is a Linux keyring prompt — it is not related to the workshop. Just leave both password fields empty and click Continue.

Step 4 — Physics layer

In Build Mode, select the physics-movement agent and provide the prompt:

@physics-movement add player movement, shooting, and collision detection

This may take 2-3 minutes. The agent is wiring up input handling, bullet physics, and hit detection.

→ Ship moves, bullets fire, enemies fall, hits register

Check your progress (optional): Refresh game.html in your browser. You can now move the ship and shoot — but there's no scoring or game-over yet.

Step 5 — Gameplay layer

In Build Mode, select the gameplay-rules agent and provide the prompt:

@gameplay-rules add scoring, levels, enemy spawning, lives, and game-over

This may take 2-3 minutes. The agent is adding the full game loop — scores, waves, lives, and end screens.

→ Fully playable game.

Attendee challenges — push the agents further

@ui-renderer

@ui-renderer add a pulsing cyan ring around the player when shield > 0
add a warp-speed animation when the level increases
make explosions leave a smoke cloud that fades slowly

@physics-movement

@physics-movement add a dodge-roll on Shift with invincibility frames and 2s cooldown
make cruiser enemies strafe side to side while descending
add a homing missile on the X key
make enemies shoot back at the player starting at level 4

@gameplay-rules

@gameplay-rules add a score combo — consecutive kills within 1.5s multiply points
add a shield power-up that drops from bombers with 15% chance
save the high score to localStorage and show it on game-over
add a survival wave at level 3 — only drones for 10 seconds

Optional — expand to 4 or 5 agents

Uncomment the relevant agent in .opencode/config.toml, then:

Agent 4 — VFX Polish

@vfx-polish add screen shake on player hit and red vignette when lives = 1
@vfx-polish add an animated nebula drifting across the star-field
@vfx-polish add a motion trail behind the player ship

Agent 5 — Boss AI

@boss-ai add a 3-phase boss called The Void Sovereign that spawns at level 5

Troubleshooting

Arrow keys not working — click the canvas to give it focus, or ask:

@physics-movement arrow keys not working — fix keyboard focus on the canvas

Wrong model selected — exit OpenCode, run lemonade launch opencode again and select option 7 or 8.

Keyring password popup — if a "Choose password for new keyring" dialog appears, leave both fields blank and click Continue. No password is needed.

Agent broke the game

git checkout game.html   # revert to last working state

Commit after each working feature:

git add game.html && git commit -m "feat: what you added"
